Projet open source qui definit : 


API d orchestration de conteneur
Des composant en complement
Format de config YAML




les services : 


Kubernetes (upstream) =
  ├── kube-apiserver       ← le serveur central
  ├── kube-controller-manager  ← surveille l'état du cluster
  ├── kube-scheduler        ← décide où placer les pods
  ├── etcd                 ← base de données du cluster
  ├── kubelet              ← agent sur chaque node
  ├── kube-proxy           ← gère le réseau
  └── un CNI (Calico, Flannel...)  ← réseau des pods






chaque container est isole dans son node et partage jute
le meme kernel mais ne se parle pas.



Kubernetes permet dans gerer de multiples nodes avec 
de multiples pods (qui ont potentiellement de multiples 
container)




NODE :   machine physique


PODS :  1 ou plus  container


CONTAINER : vrai container, docker etc.

======= Scheduler : kube-scheduler


a la creation les pods sont pending.

le scheduleur decide dans quel node il sera placed selon si il 
est le plus approprie pour y placer le node 
(place Ram/cpu) selon les contraintes





======= Controller Manager :  kube-controller-manager


il execute en fond des "goroutine" en go





elle check l etat desire et l etat reel.
font une differement

font les action pour rapproche la plus l une de l autre.
